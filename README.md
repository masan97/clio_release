# CLIO (CLimate data Input for OpenIFS)
CLIO rewrites initial condition files for the OpenIFS numerical weather prediction model maintained and developed by ECMWF (https://www.ecmwf.int/en/research/projects/openifs). CLIO is designed to supply meteorological data from CMIP6 models to OpenIFS, thus enabling OpenIFS simulations to be initialised with atmospheric states taken from any climate model (or even any weather or climate model or reanalysis). With CLIO the user can generate initial condition files with much higher horizontal and vertical resolution thanks to CLIO's interpolation routines.

We recommend the user to use CLIO on HPC platforms. While CLIO was tested on traditional laptops, we expect slow runtime when other than TL159, TL255 or TL399 resolutions are chosen. The user is also recommended to run CLIO inside the container, which ensures smooth execution, since the user is not required to install any packages or deal with shared libraries. 


# Description
CLIO is a python-based application lauched from a python script named as CLIO_start.py

Specifically, CLIO updates the following OpenIFS initial files:
1. ICMSHxxxxINIT containing spectral fields of logarithm of surface pressure (lnsp), vorticity (vo), divergence (d), and air temperature (t); 
2. ICMGGxxxxINIT containing surface boundary conditions (e.g., soil temperatures stl1-4, skin temperature skt);
3. ICMCLxxxxINIT containing climatological forcings (e.g. albedo, sea surface temperature);
3. ICMGGxxxxINIUA containing the 3D upper air fields (cloud cover, specific humidity, cloud liquid/ice/rain/snow water content).

Such files with various horizontal and vertical resolutions can be obtained from https://doi.org/10.5281/zenodo.23364583. CLIO currently supports linear reduced grids (TL159, TL255, TL399, TL639 and TL1279) and cubic octahedral grids (TCo319, TCo639 and TCo1279). In this repository initial files for one resolution (TL399) are included.

# Installation
**Requirements and dependencies:**

To istall CLIO from this repository one requires git-lfs. Please follow the installation instructions at https://git-lfs.com/. In our HPC system git-lfs can be loaded as a module.

**Git**: to copy the "clio" repository to your local directory via Git using:
```
cd your_local_directory
git lfs install
git lfs pull
git clone git@github.com:masan97/clio_release.git
cd clio_release
git checkout newbranch
```
This will clone the "newbranch"-branch of the "clio" repository.The repository includes a container where the application can be executed. Therefore the user does not need to install any packages, since all necessary libraries are present in the container. The developers recommend using the container instead of using a local environment.


Software requirements:
- cdo 2.4.3
- eccodes 2.41.0
- hdf5 1.14.6
- netcdf-c 4.9.3
- netcdf-fortran 4.6.2

Python requirements:
- metview-python 5.22
- the rest are listed in reqs-python.txt


**Setting environment:** by using the singularity image. This image is generated by converting a Docker image into a singularity image. All the software and python requirements are included in the singularity image. The Git project containing the Docker file is accessible inside container/clio-image.simg

**Setting local environment** starting by installing metview-python <https://github.com/ecmwf/metview-python>. Please check your installation by running:

```shell
python -m metview selfcheck
```

Then, you can install the remaining dependencies by using the `uv` Python package manager. If you have not yet installed `uv` on your system, you can find instructions here: <https://docs.astral.sh/uv/getting-started/installation/>.
Afterwards, you can create a fresh virtual environment and install all dependencies using:

```shell
uv sync
```

**Executing the application:**

Before running the application edit the namelist in CLIO_start.py
Further namelist options can also be set within the three main modules (if the user wants to change the default settings):
- app/src/mod_mainVARS.py
- app/src/mod_extraVARS.py
- app/src/mod_UpperAtmosVARS.py

To run the application inside the container, do the following:

```
cd container/
singularity shell --bind your_comma_separated_paths clio-image.simg
cd ../app
python3 CLIO_start.py
```


Namelist inside CLIO_start.py:

| **Name of the parameter:** | **Type:**      | **Description:**                                                                                   |
|----------------------------|----------------|---------------------------------------------------------------------------------------------------|
| workdir                    | string    | path with CLIO_start.py                                                               |
| expname                    | string    | 4-digit experiment name of the OpenIFS initial files (e.g. from ICMSHabt3INIT abt3 will be the expname)  |
| IFS_path                   | string    | The directory containing the OpenIFS initial files to be updated                      |
| grid_type                  | string    | TL1279 or TL639 or TL399 or TL255 or TL159 or TCo319 or TCo639 or TCo1279             |
| cmip_path                  | string    | Path to your input data, below this the following directories sholb be present: model/variant_lab/date_yr data|
| model                      | string    | standard name of the CMIP6 model (e.g. EC-Earth3)                                     |
| variant_lab                | string    | The variant label (i.e. the ensemble member) of the CMIP6 input data.                 |
| exp_cmip                   | string    | The CMIP6 experiment type (e.g. historical                                            |
| date_yr                    | string    | The year of your CMIP6 data                                                           |
| date_mo                    | string    | The month of your CMIP6 data                                                          |
| date_dd                    | string    | The day of your CMIP6 data                                                            |
| date_hr                    | string    | The hour of your CMIP6 data                                                           |
| CL_length                  | string    | Number of date entries in ICMCLxxxxINIT file                                          |
| if_CMIP_in_IFS_model_level | boolian   | set to `True' when the CMIP6 input data are on the same model levels as OpenIFS (either 91 or 137).|
| use_linear_hybrid2hybrid   | boolian   | Only matters when if_CMIP_in_IFS_model_level is set to False. This variable forces CLIO to use the hybrid-to-hybrid model level vertical interpolation|
| ML_input                   | string    | path of the csv file containing the model level definitions of your input data        |
| ML_input_sep               | string    | the separator of the data in your model level csv file                                |
| in_HPC                     | string    | set to 'true' when you run CLIO inside the container. In case you run CLIO in your custom environment, this should be 'false'                    |
| ERA5_source                | boolian   | set to True when you supply ERA5 data input for CLIO.                                          |
| update_SH                  | boolian   | set to True when you want to update the spectral prognostic variables in the ICMSHxxxxINIT file|
| update_GG                  | boolian   | set to True when you want to update the surface variables in the ICMGGxxxxINIT file            |
| update_UA                  | boolian   | set to True when you want to update the 3d grid-point variables in the ICMGGxxxxINIUA file     |
| update_CL                  | boolian   | set to True when you want to update the 2d variables in the ICMCLxxxxINIT file                 |
